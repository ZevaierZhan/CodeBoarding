# 外部 Agent 持续维护架构模型：P0 产品规格

状态：P0 调查与验证；正式功能尚未交付。调查与复现入口见 [可行性报告](external-agent-p0/README.md)。

## 目标与边界

外部业务分析 Agent 自己阅读代码、推理、定义逻辑组件和业务路径，将理解写入同一份可版本化模型。CodeBoarding 提供结构提取、缓存、模型操作、校验与只读展示。新会话读取旧对象，修订相同身份的对象；源码刷新不得自动覆盖解释。本路径不要求配置 CodeBoarding 内部 provider。

| 产品用户 | 职责与入口 |
|---|---|
| 项目理解者、审阅者 | 在只读模型界面搜索、展开、选择业务、查看步骤、理由、依据与变更说明；在外部 Agent 会话提出意见 |
| 业务分析 Agent | 查询结构及源码、读取已有解释、修改模型、报告依据和不确定性；通过 CLI，必要时通过共用同一操作库的 MCP |

实施 Agent 负责本次代码调查与验证，不是新增产品用户。暂不提供图形编辑、界面审批、新聊天平台、多用户协作、数据库、后台扫描或运行模拟器。业务播放是按解释组织的步骤，运行验证另行记录。

## 用户故事与验收

共同前置条件：项目具有模型身份、源码版本和模型 revision；所有写操作由 Agent 发起。写操作先校验完整候选，再原子保存；读取与失败结果可审阅。

| 故事 | 触发与主要流程 | 异常与验收标准 |
|---|---|---|
| H1 初次解释启动 | 用户提出启动问题；Agent 查入口、配置与已有对象，保存项目边界、组件及理由；用户查看 | 缺入口或动态注册未解析时保留缺口；每个事实有版本和位置，推理明确标注；不伪造启动轨迹 |
| H2 连续查看业务 A | 用户选择场景，按步骤前进，展开当前组件到文件、符号和源码 | 条件、分支与未决边可见；展开后保留场景、当前步骤与返回位置；失效依据仍有历史上下文 |
| H3 追问划分理由 | 选定对象后在会话追问；Agent 读取对象身份、理由、依据、前提，再核查并补充 | 不以已保存或用户认可代替证明；修改仍指向原对象，并产生变更摘要 |
| H4 会话调整 | 用户要求改名、边界或步骤；Agent 核查当前代码并提交修订 | 当前行为与期望不同必须并列说明；修改失败原模型完整；受影响场景列出 |
| A1 跨会话读取 | 新会话按项目、组件或场景读取已有模型和待复核绑定 | 能看到 revision、源码版本、未知字段错误及 stale 原因；未分析的部分不冒充完整 |
| A2 自主建模 | 创建、调整成员、重设父子、拆分、合并组件，并同步引用 | 名称或画面位置改变不换 ID；循环层级、悬空引用拒绝；删除被引用对象必须指定重定向或同步修订；多场景引用同一组件 |
| A3 复用公共组件 | 在旧模型上增加业务 B，引用业务 A 已有公共组件 | 不复制公共组件制造新身份；A 的解释仍存在；同一源码可作为不同逻辑组件解释的依据 |
| A4 定向维护 | 源码刷新产生事实差异；Agent 查受影响绑定及场景，修订其解释 | 未变化对象保留；移动、改名、删除不能自动认同；不确定重绑定保留旧路径、版本、内容摘要和候选 |
| A5 管理不确定性 | 保存假设、推断关系、设计意图推测、分歧、缺边及拟验证方式 | 假设不计为事实；未执行测试不计为验证；后续修订可关闭问题并引用实际结果 |

## 模型语义与操作契约（建议，尚未实现）

建议在同一项目模型中以关联结构引用原生事实快照。逻辑对象身份采用独立 opaque ID；不把名称、目录、原生点分层级 ID 或步骤位置当作身份。初版用 `architecture-model.json` 保存解释，用原生 `analysis.json` 或专用事实导出保存可重建的代码索引；这是同一模型的两个存储工件，不是两轮独立图。

| 信息 | 最小内容与来源 |
|---|---|
| 源码绑定 | binding_id、文件、qualified_name、符号类型、源码版本、内容 hash、历史位置、状态（current/changed/missing/ambiguous）、候选；原生 method key 作为版本内查找键 |
| 架构组件 | component_id、name、responsibility、rationale、parent_id、members/binding_ids、前提、证据、问题；作者与修订 |
| 关系解释 | 独立关系 ID、端点、含义、evidence_ids、claim_kind；动态注册/配置证据允许补充静态缺边 |
| 业务场景 | scenario_id、入口、步骤 ID、有序展示列表、显式转移（条件/分支/返回）、组件和函数引用、子场景引用、每步解释和依据；禁止用图边顺序推定执行顺序 |
| 用户意见 | 原始意见、关联对象、认可/纠正/分歧；不会提升 claim_kind 为 code_fact |
| 实际验证 | 版本、输入、环境、命令、退出码、输出摘要、时间与执行者；planned 和 executed 区分 |
| 修订与待复核 | revision、expected_revision、change_summary、受影响对象/场景、旧依据上下文；原子快照即可，无需事件溯源 |

主循环：读取模型 → 查询结构 → 回源码核实 → 形成候选修改 → 校验身份/引用/来源/版本 → 原子提交 → 用户只读查看 → 会话纠正 → 修订同一模型。源码更新只更新事实与绑定状态；解释更新是另一个明确操作。源码匹配成功也不能自动证明旧解释仍然正确。

首版操作库与 CLI 至少提供：

1. `model read --project/--component/--scenario`：含相关依据、revision 与待复核内容；范围读取声明范围，避免把省略误当删除。
2. `facts query` 与 `source read`：按文件/符号/调用/配置查询；返回固定版本和位置；静态缺边仍允许直接读源码。
3. `model apply --expected-revision N --patch FILE`：以稳定 ID upsert 对象；明确字段替换语义，数组整体替换，不按下标作为身份；创建不得覆盖既有 ID。
4. `split/merge/delete/reparent`：作为一次候选修改，提供保留 ID、新 ID、引用重定向、成员与场景变更；校验无环与完整引用后一起提交。拆分不能把原对象 ID 同时给两个新对象。
5. `facts refresh`：读取新事实快照，比较 hash；明确标出 changed/missing/ambiguous，列出受影响场景。失败不丢旧事实与解释。
6. `model validate/diff`：返回稳定错误码、对象位置、候选变更和影响；提交失败不改变文件与 revision。

读取错误、revision 冲突、悬空引用、层级循环、未知字段、失效源码版本、写失败是显式错误。失效 binding 可持久化为待复核对象，但不得伪装成 current；不从错误恢复成全量重建。

## 正式 MVP 的连续验收

固定一个可重放的项目，按以下顺序验收同一模型：

1. 解释启动并保存边界、组件、理由及源码依据；只读查看。
2. 新进程/会话读取模型，增加业务 A，再增加 B；公共 component_id 相同，启动解释仍存在。
3. 会话要求跨目录调整成员与层级；校验并修订所有相关场景，展示理由与摘要；改名不换身份。
4. 编辑源码，刷新事实；未变化解释保留，失效或变化引用标出；Agent 修订后关闭待复核，历史依据仍可追溯。

P0 实验仅覆盖静态提取、语义回填、保存重读、HTML 展示、内部 API 成员移动和一次函数体编辑的静态 warm start。它不覆盖上述完整会话流程、场景播放、生产模型操作或可靠跨版本重绑定。

## 实施里程碑

| 阶段 | 用户故事与范围 | 依赖、验收和不确定性 |
|---|---|---|
| M1 模型操作与无 provider 事实入口 | A1/A2/A3/A5、H1/H3/H4；共享操作库、严格 schema、文件 CLI、结构导出 | 依赖 P0 StaticAnalyzer/ScopeAssembler；跨进程重读、跨目录定义、split/merge/reparent 引用一致、失败文件不变、provider 入口不可调用；多语言事实质量仍需逐语言验证 |
| M2 源码维护 | A4/H4；事实刷新、binding 状态、影响查询 | 依赖 M1；函数体编辑、行移动、文件移动、改名、删除、完整重建案例；保留解释；模糊匹配不得自动确认；大仓库性能未验证 |
| M3 只读场景视图 | H1/H2/H3；稳定 ID 视图、搜索、层级、步骤、依据、差异 | 依赖 M1/M2；完整四轮验收，展开保留当前步骤；优先本地公开展示层；VS Code/Web 平台授权和 API 可用性仍待确认 |

### 下一阶段第一项开发任务：独立模型操作库与 CLI

在主 fork 新增独立 `architecture_model/` 模块及 CLI 子入口，避免进入现有 analysis bootstrap。先实施 `read/validate/apply/diff` 和受控 Python `facts export`，只用显式 LSP 工具配置和原生静态 API。保留 native `analysis.json` 作为事实投影，写解释到专用文件；不调用 `ScopeAnalysisAgent`。

输入：本规格、P0 fixture、实际解析与保存实验。输出：严格 schema v1、操作协议、无 provider CLI、一个可跨进程复用的样例模型、错误码和失败回滚测试。opaque ID 与 parent_id 分离；源码绑定采用 ID+版本内 method key；场景步骤引用组件，不复制组件。

开发验收：先保存启动解释，再新进程读取并添加 A/B；同一公共组件被复用；一次跨目录拆分/合并和重设层级更新场景引用；错误 revision、重复 ID、循环 parent、删除被引用对象和模拟磁盘失败均保留原文件；新增未知字段拒绝；无 provider 配置时导出 fixture 三条调用边且模型操作无模型初始化。M1 暂仅报告 binding 状态，不实现自动 rename 推断或业务播放。测试关注事务与引用一致性，不镜像内部实现。
